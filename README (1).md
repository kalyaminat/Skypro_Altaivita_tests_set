# Тестирование сайта Алтайвита

Учебный проект по тестированию сайта [Алтайвита](https://altaivita.ru/). В нём собраны материалы для ручного тестирования поиска и корзины, Postman-коллекция, SQL-запросы и автотесты API и пользовательского интерфейса. Проект выполнен в рамках обучения в Skypro и дополнен при подготовке портфолио.

## Состав проекта

| Материал | Содержание |
| --- | --- |
| Чек-лист поиска (`.xlsx`) | Функциональные, негативные и кроссбраузерные проверки поиска |
| Postman-коллекция (`.postman_collection.json`) | Добавление товара, просмотр корзины, изменение количества, удаление и негативный сценарий |
| `sql.sql` | Пять запросов к учебной базе «Полезные продукты» |
| `api_tests.py`, `apipages/` | API-тесты корзины и клиент для работы с запросами |
| `ui_tests.py`, `uipages/` | UI-тесты корзины и классы страниц |
| `conftest.py` | Подготовка браузера и гостевой API-сессии |
| `requirements.txt`, `pytest.ini` | Зависимости и настройки запуска pytest |
| Архив с видео (`.rar`) | Видеокомментарий к выполненной работе |

Названия файлов чек-листа и коллекции могут отличаться в локальной копии. Исторические статусы ручных проверок приведены в самом чек-листе и относятся к указанному там периоду.

## Автотесты

**API:** добавление товара в гостевую корзину, удаление товара и запрос информации о корзине. Каждый тест получает отдельную гостевую сессию; тест удаления предварительно добавляет товар.

**UI:** добавление товара и проверка суммы мини-корзины; сравнение суммы товаров на странице корзины с мини-корзиной; удаление единственного товара и проверка нулевой суммы.

Стек: **Python, pytest, requests, Selenium WebDriver, Page Object Model и Allure Pytest**.

### Установка и запуск на Windows

Требуются Python, Google Chrome и доступ к сайту. Команды выполняются в PowerShell из корня проекта. Если папка `venv` уже создана, создавать её заново не нужно.

```powershell
python -m venv venv
.\venv\Scripts\python.exe -m pip install -r requirements.txt
```

Запуск всех тестов:

```powershell
.\venv\Scripts\python.exe -m pytest -v
```

Только API или только UI:

```powershell
.\venv\Scripts\python.exe -m pytest api_tests.py -v
.\venv\Scripts\python.exe -m pytest ui_tests.py -v
```

Для API-тестов используется гостевая сессия: в процессе подготовки клиент получает cookie сайта. UI-тесты открывают Chrome. Тесты изменяют содержимое гостевой корзины, но не оформляют заказ.

Если Requests использует системный прокси и соединение с сайтом через него не устанавливается, можно для текущего окна PowerShell задать исключение:

```powershell
$env:NO_PROXY = "altaivita.ru"
```

После завершения работы в этом окне настройку можно удалить командой `Remove-Item Env:NO_PROXY`. Проверку сертификатов отключать не требуется.

### Отчёт Allure

`pytest.ini` сохраняет результаты в `allure-files`. Для просмотра HTML-отчёта дополнительно нужна установленная утилита Allure Report 2:

```powershell
allure serve allure-files
```

Результаты разных прогонов могут сохраняться в одной папке. Для отдельного отчёта перед новым прогоном нужно очистить старые результаты или указать другую директорию через `--alluredir`.

## Postman-коллекция

Импортируйте файл коллекции в Postman. Для работы с корзиной используется гостевая сессия: в переменную `s_cid` нужно записать актуальное значение cookie `CID`, а поле `S_customerID` оставить пустым. Значения сессии и позиции корзины устаревают; их не следует публиковать как рабочие данные.

Перед последовательным прогоном нужно проверить, что корзина пуста, и использовать один товар. После добавления запрос просмотра корзины получает `itemID` выбранного товара для изменения количества. Если в корзине несколько товаров, общий счётчик и сумма включают все позиции.

Коллекция содержит негативный запрос с несуществующим ID. Ожидаемую обработку ошибки и состояние корзины следует сверять с фактическим ответом сайта. Время ответа зависит от сети и сервера; тестовый порог сам по себе не является согласованным требованием производительности.

## SQL

Схема учебной базы включает таблицы `products`, `categories` и `nutritional_information`. Запросы выводят уникальные названия, продукты с клетчаткой более 5 г, продукты с максимальным содержанием белка, сумму калорий по категориям и среднюю цену в категории.

SQL проверен по предоставленной схеме на пустых таблицах SQLite. Результаты на исходных учебных данных не проверялись. Запрос на максимум белка возвращает все продукты с одинаковым максимальным значением; средняя цена выводится для категорий, содержащих товары.

## Статус и ограничения

При локальном запуске обновлённых автотестов прошли **6 из 6**: три API- и три UI-теста. В том запуске использовалось исключение прокси для `altaivita.ru`. Это результат конкретного прогона, не гарантия будущих запусков.

Сайт, товары, цены, локаторы и формат ответов могут изменяться. Доступность сервиса, сетевые настройки и защитные механизмы также влияют на выполнение проверок. Postman-коллекция и инструкция должны использовать актуальные данные гостевой сессии.
